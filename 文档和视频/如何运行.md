# 项目运行

## 1. 创建虚拟环境（Python 3.13.5）

```bash
python3.13 -m venv venv
source venv/bin/activate   # macOS/Linux
# venv\Scripts\activate    # Windows
```

## 2. 安装依赖

```bash
pip install -r requirements.txt
```

## 3. 配置 LLM

编辑项目根目录下的 `config.py`，填写你的模型 API 信息：

```python
LLM_CONFIG = {
    "model_name": "模型",
    "base_url": "你的 Base URL",
    "api_key": "你的 API Key",  
}
```

## 4. 启动数据服务（PostgreSQL + Redis）

没启动也能跑（自动降级为 JSON 文件 / 进程内存），但建议启动：

```bash
# PostgreSQL
brew services start postgresql@16

# Redis
~/redis/redis-server --port 6380 --daemonize yes --save '' --appendonly no
~/redis/redis-cli -p 6380 ping            # 验证：应返回 PONG
```

连接配置见 `config.py` 的 `POSTGRES_CONFIG` / `REDIS_CONFIG`。首次在新机器上使用时，需先建库建用户（一次性）：

```bash
/opt/homebrew/opt/postgresql@16/bin/psql -U $USER -d postgres \
  -c "CREATE USER shanglv WITH PASSWORD 'shanglv';" \
  -c "CREATE DATABASE shanglv OWNER shanglv;"
```

所有表结构在服务首次启动时自动创建（`CREATE TABLE IF NOT EXISTS`），无需手动建表；已存在的旧 JSON 记忆（`data/memory/{user_id}.json`）会在该用户首次接入时自动迁移进 PG。

## 5. 初始化知识库

```bash
python skills/ask-question/script/init_knowledge_base.py
```

脚本会切分 `skills/ask-question/data/documents/` 下的知识库文档并建立向量索引（依赖本地 Embedding 模型 `data/models/bge-m3/`）。

## 6. 启动 pi-durable 服务

需要 Node ≥ 22.19。不启动也能跑（自动降级本地路径）。

从本章开始，每个服务都会占住一个终端（日志实时刷屏），一共需要 3 个终端（Cmd+T 新开）。

**终端 1** —— pi-durable：

```bash
cd services/pi-durable && npm install && npm run build
AIGC_APP_ID=<config.py 里 api_key 的值> INTENT_MODEL=<config.py 里 model_name 的值> node dist/index.js
```

令牌已内置默认值，无需配置。同一 sqlite 只允许一个 pi-durable 实例；`PI_DURABLE_ENABLED=0` 整体关闭。

## 7. 启动

**CLI 模式**（只需终端 2，不用终端 3）：

```bash
python cli.py          # 终端 2
```

输入用户 ID（回车用默认）后即可对话。子命令：`help` / `status` / `health` / `clear` / `history` / `preferences` / `exit`。

**Web 模式**（需要终端 2 和终端 3）：

```bash
python -m uvicorn server:app --host 0.0.0.0 --port 8000   # 终端 2：API
cd web-next && npm run dev                                 # 终端 3：前端（首次需 npm install）
```

浏览器打开 **[http://localhost:3000](http://localhost:3000)**。

## 评测

统一入口 `tests/eval/run_eval.py`，评测集 `tests/eval/cases.json`（100 条，12 意图分层覆盖，数据文件加题改文件即可）。

跑完输出一份报告（`tests/results/eval_<时间戳>.md`），包含：

- **四个总指标**：意图路由准确率 / 端到端 Pass@1 / 内容验收率 / 延迟 P50-P95
- **分意图通过率表**（12 个意图）
- **失败明细**：每条附期望 vs 实际路由、回答头部（定位是路由错了还是答案错了）
- **多轮场景**：同一会话连续对话的跨轮行为（规划→改偏好→重规划、缺要素追问→补充续跑、费用预估→改天数重算）
- **会话隔离检查**：不同用户/会话数据不串
- **pi-durable 链路检查**：通过 /chat 发一轮真实请求，验证全链路确实跑在 pi-durable 任务树上
- **Rubric 质量评分**：LLM-as-Judge 按多准则（相关性/事实依据/完整性/清晰度/敏感合规）逐条打分，产出 Rubric 均分与分意图表；结果按指纹缓存，重跑不重复调用
- **回流数据分级**：每条评测结果（query/路由/回答/耗时/各层判定）落盘 JSONL，并按 KEEP（可用）/ REVIEW（待人工复核）/ REWRITE（需修正）三级打标，作为可复用的数据资产
- **确定性校验器检查**：坏输出（预算算术错误、假无冲突）必须被代码校验抓到，合规输出不误伤

```bash
venv/bin/python tests/eval/run_eval.py
```

改代码后重跑全量，对比两份报告的指标即可看回归。Rubric 结果按指纹缓存——回答没变的 case 重跑不会重复调 Judge。评测产物（都在 `tests/results/`）：报告 `eval_<时间戳>.md`、结构化结果 `eval_<时间戳>.json`（每 case 全字段）、回流数据 `backflow_<时间戳>.jsonl`（三级打标）。
